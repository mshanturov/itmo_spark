# Отчёт по лабораторной работе №6

**Дисциплина:** Инфраструктура больших данных  
**Тема:** Источники данных на PySpark (MongoDB)

## 1. Цель работы

Получить навыки выгрузки исходных данных и отправки результатов модели
с использованием внешнего источника данных (MongoDB).

## 2. Реализация

Разработан пайплайн `src/lab6_mongo_pipeline.py`, который выполняет:

1. Проверку/инициализацию источника данных (опционально bootstrap).
2. Выгрузку данных из MongoDB при каждом запуске модели.
3. Предобработку данных в Spark.
4. Запуск модели KMeans и выбор лучшего `K` по silhouette.
5. Немедленную загрузку результатов модели в MongoDB.
6. Запись статусов выполнения в коллекцию `pipeline_runs`.

## 3. Протокол взаимодействия модель ↔ источник данных

Протокол описан в `PROTOCOL_LAB6.md`.

Ключевые состояния запуска:
- `started`
- `bootstrapped` (при пустом источнике)
- `exported`
- `completed`

Для каждого запуска формируется уникальный `run_id`.

## 4. Формат хранения данных

### Исходные данные (`openfoodfacts_source`)
Хранятся как документы MongoDB с ключами `code`, `product_name`, `nutriments`, `source`.

### Результаты (`kmeans_results`)
Для каждой записи сохраняются:
- `run_id`, `processed_at`, `model`
- метрики модели (`best_k`, `best_silhouette`)
- признаки (`features`)
- присвоенный кластер (`cluster_id`)

### Служебные метаданные (`pipeline_runs`)
Сохраняется состояние протокола и агрегаты запуска (количество выгруженных/загруженных строк).

## 5. Docker

Добавлены:
- `Dockerfile` (PySpark + Java + Python dependencies)
- `docker-compose.yml` (сервисы `mongodb` и `model-pipeline`)

Пример запуска:
```bash
docker compose up --build model-pipeline
```

## 6. Результаты

Выполнены требования задания:
- обеспечена выгрузка при каждом запуске;
- обеспечена загрузка результатов сразу после завершения модели;
- разработан протокол взаимодействия;
- разработан формат хранения данных в MongoDB;
- подготовлен контейнерный запуск.
