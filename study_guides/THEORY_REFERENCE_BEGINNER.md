# Теоретическая справка (для новичка)

Этот файл — короткая теория, чтобы было легче понимать, *зачем* в лабах нужны те или иные инструменты.

## 1) Что такое ML-пайплайн

ML-пайплайн — это последовательность шагов:

1. Получить данные.
2. Подготовить данные (очистка, split, признаки).
3. Обучить модель.
4. Проверить качество.
5. Выдать модель как сервис (API).
6. Автоматизировать (CI/CD, контейнеры).

Главная идея курса: не только «обучить модель», а **довести её до инфраструктурно зрелого сервиса**.

---

## 2) Что такое CI/CD в контексте ML

- **CI (Continuous Integration)**: при изменении кода автоматически идут проверки (тесты, сборка образа).
- **CD (Continuous Delivery/Deployment)**: автоматический запуск сервиса и функциональные проверки.

Почему это важно:
- меньше ручных ошибок;
- стабильное качество;
- воспроизводимость.

---

## 3) Зачем Docker

Docker делает «одинаковое окружение» везде:
- у тебя локально,
- на CI-сервере,
- у преподавателя,
- в Kubernetes.

Если «у меня работает, у вас нет» — обычно это проблема окружения. Docker это сильно уменьшает.

---

## 4) Spark / PySpark простыми словами

Spark — движок для обработки данных (в т.ч. больших).

- **Driver**: «мозг» задачи.
- **Executors/Workers**: выполняют вычисления.
- **DataFrame API**: удобная обработка таблиц.

PySpark — Python-интерфейс к Spark.

---

## 5) Redis vs MongoDB vs Kafka

### Redis
- key-value хранилище в памяти;
- очень быстрое;
- удобно для временных данных, кэша, быстрых lookup.

### MongoDB
- document-oriented БД (JSON-подобные документы);
- удобно хранить полуструктурированные записи.

### Kafka
- брокер сообщений;
- producer публикует события, consumer читает их;
- подходит для event-driven архитектуры.

---

## 6) Что такое Vault (на примере Ansible Vault)

Vault нужен, чтобы **не хранить секреты в открытом виде** в коде/репозитории.

В нашем контуре:
- секреты шифруются,
- при запуске контейнеров расшифровываются,
- сервисы читают их из файлов/переменных.

---

## 7) Что такое Data Mart (витрина данных)

Витрина — слой между моделью и источником:
- унифицирует формат;
- готовит/фильтрует данные;
- отдаёт модели уже подготовленный набор.

Плюсы:
- меньше логики в модели;
- единый формат для разных потребителей;
- проще масштабировать.

---

## 8) Что такое Kubernetes и Helm

### Kubernetes
Система оркестрации контейнеров:
- запускает и перезапускает контейнеры,
- масштабирует,
- даёт networking и service discovery.

### Helm
Менеджер шаблонов для Kubernetes:
- вместо десятков YAML можно хранить шаблоны,
- значения меняются через `values.yaml`.

---

## 9) Что значит “поэтапная миграция”

Сразу переносить всё в k8s рискованно. Поэтому делаем ступени:
1. Сначала модель,
2. потом источник,
3. потом витрина.

Так проще локализовать проблемы и убедиться, что каждая стадия рабочая.

---

## 10) Мини-чеклист хорошей лабораторной

- Есть понятный запуск.
- Есть тесты / валидация.
- Нет хардкода секретов.
- Есть отчёт и протокол взаимодействия.
- Есть контейнеризация.
- Есть воспроизводимый дистрибутив (zip).
