## 1. Зачем вообще нужна такая архитектура

Если делать «по-учебному в 1 файле», ты не сможешь:
- повторить результат;
- быстро проверить, что не сломал модель;
- передать проект другому человеку.

Поэтому ЛР1 строится как **инженерный конвейер**:
- `preprocess.py` — данные,
- `train.py` — обучение,
- `predict.py` — оценка,
- `api_service.py` — интерфейс сервиса,
- `config.ini` — параметры,
- `Dockerfile`, `docker-compose.yml` — запуск в контейнерах.

## 2. Пошагово: как это разрабатывалось бы с нуля

### Шаг 1. Подготовка каркаса
Создаётся структура папок `src/`, `tests/`, `experiments/`, `data/`.

### Шаг 2. Загрузка и разрезание данных
В `src/preprocess.py` создаётся класс `DataMaker`.

Ключевая идея:
- один раз загрузить сырой файл;
- разложить на `X` и `y`;
- split на train/test;
- сохранить пути в `config.ini`.

Пример кода:
```python
x_train, x_test, y_train, y_test = train_test_split(
    x_data,
    y_data,
    test_size=test_size,
    random_state=random_state,
    stratify=y_data,
)
```

`stratify=y_data` важно: сохраняет баланс классов в train/test.

### Шаг 3. Обучение моделей
В `src/train.py` класс `MultiModel` читает пути из `config.ini`, масштабирует признаки и обучает модели.

Пример:
```python
self.scaler = StandardScaler()
self.x_train = self.scaler.fit_transform(self.x_train)
self.x_test = self.scaler.transform(self.x_test)
```

Почему так:
- без масштабирования часть моделей (SVM, KNN, LogReg) могут работать хуже.

Модели сохраняются в `.sav`:
```python
with output_path.open("wb") as file:
    pickle.dump(classifier, file)
```

### Шаг 4. Проверка (smoke + functional)
В `src/predict.py`:
- smoke — быстрая проверка на тестовой выборке;
- functional — прогон по подготовленным JSON-сценариям.

### Шаг 5. API слой
В `src/api_service.py` делается endpoint `/predict`, который принимает признаки и отдаёт класс.

### Шаг 6. Контейнеризация и автоматизация
Добавляются Docker + Jenkins pipelines + zip-сборка.

## 3. Подробный разбор ключевых файлов

## `src/preprocess.py`

### Что делает класс `DataMaker`
- Читает `config.ini`.
- Проверяет наличие сырого датасета.
- Если файла нет — скачивает с UCI.
- Формирует CSV для `X` и `y`.
- Делает train/test split.

Почему классом:
- удобно хранить пути/настройки в `self.*`;
- проще расширять.

## `src/train.py`

`MultiModel` содержит методы для каждой модели:
- `log_reg`
- `rand_forest`
- `knn`
- `svm`
- `gnb`
- `d_tree`

Плюс общий метод сохранения:
```python
def save_model(self, classifier: object, name: str, params: dict[str, str]) -> bool:
    ...
```

Это централизует запись модели и конфигов.

## `src/predict.py`

Важный момент: в functional тестах не просто считается score, а создаётся папка эксперимента:
- `exp_config.yaml`
- копия логов
- копия `.sav`

То есть появляется **трассируемость эксперимента**.

## `config.ini`

Это «сердце конфигурации»:
- пути к данным,
- параметры моделей,
- путь к моделям,
- дефолтная модель API.

Плюс: параметры можно менять без изменения кода.
